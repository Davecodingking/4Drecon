单图场景重建里的穿模与墙地问题

现状：家具用 SAM 3D 逐个生成，MoGe 拟合地面法线当 z-up，歪头和悬空已经解决；剩下两件事——物体之间穿模，以及墙、地板、天花板这类大面积结构怎么表示。下面梳理 2024–2026 年直接相关的工作，重点看谁的做法能直接搬到我们这条线上。

整理于 2026-08-27覆盖 26 篇工作重点：SAM 3D 系（4 篇）、物理后处理、房间结构

结论先行

  1. 穿模问题已经有一条成熟且和我们完全同构的路线：2026 年出了四篇"SAM 3D 逐物体生成 + 事后物理整理"的工作（REST3D、ϕ-Scene、RoboSnap、SimuScene），做法都是三步：推断"谁支撑谁"的支撑图 → 按支撑顺序用 SDF 逐个消除穿插 → 扔进刚体模拟器让它落稳。我们的 scene_phys.py 已经走完第一步（几何规则版支撑图 + 扶正 + 落地），差的是后两步。REST3D 报告 SAM 3D 原生的物体碰撞率 41.8% 降到 2.7%，稳定率 8.9% 升到 94.9%。
  2. 最省事的切入点是 MV-SAM3D：它直接在 SAM 3D 的 flow 采样里加"体积重叠惩罚 + 接触约束"的引导，再对输出 mesh 做位姿微调，碰撞率 15.3% → 0，代码公开。我们已经有 SAM 3D 环境，理论上是"加一段引导"而不是换模型。
  3. 墙、地、天花板：没有任何一篇用物体生成器去生成它们。所有工作都把房间结构当"平面"处理——从深度点云按语义 mask 做 RANSAC 拟平面、相邻平面求交线裁成多边形（Diorama、ACDC、RoboSnap）；被家具挡住的部分要么先"去家具化"补全图再估深度（Diorama、Li 2025），要么用小 MLP 拟合 SDF 让它自动插值（Gen3DSR）。我们手里 MoGe 点云 + SAM 3 的 wall/floor/ceiling mask 已经齐了，缺的只是这一步拟合。
  4. 联合生成（MIDI、SceneGen、PixARMesh）目前不能替代后处理：它们靠训练数据学"合理布局"，没有硬约束，SceneGen 自己承认仍会穿插；而且都只在 3D-FRONT 合成室内数据上训练。

我们的流水线缺什么

把现在的链路摆出来，缺口就清楚了。虚线框是文献里有成熟做法、我们还没接的环节。

有SAM 3 按类别 / 点选出实例 mask
有SAM 3D 逐物体生成形状 + 相机系位姿
有MoGe 点云 → 地面法线 → z-up，解决歪头/悬空
有 · 几何规则版支撑关系（scene_phys.py）：脚印覆盖 + 台面高度找"脚下是什么"，先支撑后被支撑，挂墙/吊顶/软物分类处理
部分去穿插：scene_fix.py 按 AABB 相交体积推开；文献用 SDF 接触约束（穿进去罚、离开也罚）
缺刚体模拟落稳；墙/地/天花板作为平面重建，被遮挡部分补全（现在墙地是 SAM 3D 物体 + 深度对齐）

和文献比，支撑图这一步我们不缺，差别在来源：我们用几何 + 类别白名单推断，文献多用 VLM 从图里读语义关系。几何版的好处是确定、不用 API；VLM 版能回答几何回答不了的问题——"支撑物没被分割出来"（报告里 4 个"未知"）、靠着墙（lean）、放在容器里（contained）、椅子半塞在桌下。两者可以叠加：几何版给默认，VLM 只裁决"未知"和冲突。

SAM 3D 论文自己的定位（arXiv 2511.16624）：对每个 mask 独立预测 (R, t, s)，"没有任何物体间推理，不做碰撞检测和场景级约束"；pointmap 只是可选条件，且"形状质量不依赖 pointmap"；不重建墙地背景。它提供的唯一场景级手段是 render-and-compare 的事后位姿优化——就是我们 --layout 开关那个，逐物体独立、只对齐轮廓，管不了穿模。

一、穿模 / 悬空 / 支撑：五条路线

把 2024–2026 的工作按"约束加在哪一步"分成五类。对我们最有用的是 A、B、C，因为它们都不动生成器。

A · 先问 VLM"谁支撑谁"

CAST · REST3D · ϕ-Scene · Diorama · ACDC · RoboSnap

把带编号 mask 的图交给 GPT-4V / Gemini，输出每个物体的支撑父节点（地面 / 墙 / 天花板 / 某物体）和关系类型。CAST 的技巧值得抄：不直接问 support/contact，先问更细的 Stack / Lean / Hang / Clamped / Contained / Edge，多次随机着色投票（>50% 才采纳），再折叠成"支撑（有向）"和"接触（无向）"两种边。REST3D 把根节点固定成 ground / wall / ceiling / ground-wall 四个，物体是"on / hanging / attached"。有了这张图，后面的优化就有了顺序（拓扑排序）和目标（贴住父节点表面）。

B · SDF 位姿优化去穿插

CAST · ϕ-Scene · RoboSnap · ACDC · Diorama（SAT）

每个物体 mesh 预计算 SDF；按支撑顺序逐个放置，只优化平移（ϕ-Scene）或旋转+平移（CAST），尺度冻结。ϕ-Scene 的损失最简洁：在当前物体和已放好的上下文物体表面各采 2048 点，双向算清距离，穿进去罚、离开超过 ε=0.005 也罚（保证接触而不是悬空），Adam lr 5e-3 最多 300 步。CAST 另加"支撑约束"（单向，把被支撑物拉到支撑面）和对地面/墙这类平面的特殊正则。Diorama 用的是凸多边形分离轴定理，粗但快。

C · 刚体模拟落稳

ϕ-Scene（Blender）· REST3D（Isaac Gym）· RoboSnap（SAPIEN）· SimuScene

SDF 只保证"不穿"，不保证"站得住"。做法：VHACD 凸分解当碰撞体，按支撑顺序逐个释放，重力下模拟 60–120 帧，位姿变化小于阈值即落稳。REST3D 更进一步，把模拟结果当能量函数（稳定性漂移 + 峰值速度 + 凸包穿插 + 与原布局偏差），用交叉熵法（CEM，每轮 2048 个候选）在 Isaac Gym 里搜 6-DoF 位姿，先按支撑树局部优化再全局优化。SimuScene 反过来用模拟当"诊断"：掉下去或穿插就回去改形状（沿重力轴拉伸、重采样 amodal 形状）。

D · 生成过程中加约束

MV-SAM3D · PhyScene · SceneGen

MV-SAM3D 在 SAM 3D 的 flow-matching 轨迹上加物理引导（罚体积重叠、要求接触），输出后再做一次带碰撞/接触约束的位姿优化，多物体碰撞率 15.32% → 0，空间准确率 60% → 92%。PhyScene（CVPR 2024）是布局扩散模型上加碰撞/房间边界/可达性引导，思路同源但对象是布局合成不是重建。SceneGen 用 64³ 体素上的重叠损失训练，作者承认仍会穿插——训练时的软约束不如推理时的硬约束。

E · 联合建模让模型自己学

MIDI · PixARMesh · SceneGen · DepR

MIDI 在多实例间加注意力，PixARMesh 把位姿和网格串成一条自回归序列，SceneGen 用场景级自注意力。共同点：布局合理性来自 3D-FRONT 先验，没有显式碰撞项，也不重建背景。我们上午跑的 PixARMesh 结果印证了这点——布局连贯，但尺寸偏大、局部仍有交叠。适合当参考，不适合当我们的物理保障。

旁支 · 可微物理直接进重建

PhyRecon（NeurIPS 2024）

把粒子刚体模拟做成可微，和体渲染一起训练隐式表面，稳定性提升 40%+。但它是多视角 NeRF/SDF 路线，和我们单图 + 生成式的设定不同，只作为"物理损失可以直接反传到几何"的参考。

二、墙、地、天花板与背景

你观察到的现象——用 SAM 3D 逐块生成墙体会断裂、地板不完整——文献里没有人试图用物体生成器解决，原因很简单：生成器学的是"有边界的物体"，墙地是被画幅切断的无边界平面，模型只能脑补一个盒子。可用的表示分四档，按几何干净程度从高到低：

1 · 语义平面（推荐）

Diorama · ACDC · RoboSnap · REST3D · Total3D 传统

用 wall / floor / ceiling 的 mask 从度量深度点云里切点，每块 RANSAC 拟一个平面，法线聚类合并共面块，相邻平面求交线得到墙角、墙脚线，裁成多边形。Diorama 的 PlainRecon 三步（去家具 → Metric3D v2 → 法线聚类 + RANSAC + 凸包）是最完整的描述。产出是几十个面的干净板子，正好和紧凑家具网格风格一致，也能直接当物理碰撞体。缺点：只能表达平面，弧形墙、拱门要另处理。

2 · 先"去家具"再估深度

Diorama（LaMa）· Li 2025（专训 inpainting）· RoboSnap

被沙发挡住的那段墙脚在深度图里根本不存在。做法：把家具 mask 抠掉用 inpainting 补成空房间图，再估深度，就能得到完整的墙地平面。Diorama 用现成 LaMa；Li 2025（arXiv 2512.17955）专门训练了预测房间布局的 inpainting 模型并配"混合深度估计"，在 3D-FRONT 上超过 SOTA。这一步是"地板不完整"的直接解药。

3 · 隐式曲面自动插值

Gen3DSR（3DV 2025）

不分平面，把所有"stuff"像素反投影的点交给一个小 MLP 拟合 SDF（另一个拟颜色），marching cubes 抽面；被遮挡的区域由网络根据周围自动插值。优点是不限于平面、实现简单；作者承认大面积遮挡处会有洞和细节不足，且物体和背景之间无约束、会互相穿插。

4 · 视觉背景幕布（3DGS / 深度片）

RoboSnap · HunyuanWorld 1.0 · TelePhysics

不追求干净几何，只要看起来对：RoboSnap 用世界模型把补全后的背景生成 3DGS，再用稀疏对应对齐到重力系；HunyuanWorld 把全景图分成天空 / 背景 / 物体三层，背景用"深度片翘曲 + 自适应深度压缩"做成网格。适合展示和漫游，不适合物理和编辑。可以和第 1 档叠加：平面当碰撞体，3DGS 当外观。

拿"结构"而不是"面"的工具

  • SpatialLM（NeurIPS 2025，代码 + HF 权重）：输入点云，LLM 直接输出墙段、门、窗和物体有向框的 Python 结构。在 5.5 万个合成房间上训练，对我们 MoGe 单目点云的鲁棒性要试；但一旦可用，墙的拓扑（哪几面墙、门开在哪）就是免费的。
  • Layout Anything（arXiv 2512.02952）、uLayout（arXiv 2503.21562）：单张透视图直接出房间布局线（墙-地、墙-墙、墙-天花板边界），已知内参就能升成平面。适合家具遮挡严重、点云拟合失败的情况做兜底。
  • ZeroPlane（CVPR 2025 Highlight，代码）：野外单图平面检测 + 法线/偏移重建，14 个数据集 56 万标注训练。可替代"mask + RANSAC"那一步，直接给每块平面。
  • 经典参照：Total3DUnderstanding（CVPR 2020）和 InstPIFu（ECCV 2022）把房间当一个长方体布局框和物体联合预测——现在看太粗，但"布局框 + 物体位姿 + 网格"三件套的问题定义就是从它们来的。
四档的共同前提：深度要是度量尺度且重力对齐。ϕ-Scene 和 PixARMesh 都指出单目深度是最大误差来源；我们的 MoGe-2 已是度量深度，地面法线也有了，所以第 1、2 档的门槛主要在工程上。

三、重力方向与相机：你已经做对的部分，以及可以加固的地方

"MoGe 拟地面法线当 z-up"和文献是一致的：RoboSnap 用 VGGT 前景点拟支撑平面定重力系，TelePhysics 把所有物体锚到一个标准地面平面，REST3D 用落地物体的主竖直轴对齐重力。两个可以加固的点：

  • 地面看不见时的兜底：用 GeoCalib（ECCV 2024）或 PerspectiveFields 直接从图像估重力方向和焦距，不依赖地面 mask。ϕ-Scene 的代码库里就留着 PerspectiveFields 的调用。
  • 再加一个偏航：拟出墙面法线后，把主墙对齐 x 轴，得到曼哈顿坐标系。REST3D 用这个把挂墙物体贴到墙上；对我们，等于让后续所有位姿优化都在"房间坐标"里做，物体的 yaw 也有了参照。

四、给我们流水线的具体建议

按"改动小、收益大"排序。前三条不动 SAM 3D 本身，都是在现有 run_scene.py 之后加一段。

1

在 scene_phys.py 的"规则三"位置接 SDF 去穿插（ϕ-Scene / CAST 配方）

支撑图和放置顺序已经有了，直接复用。把现在"只报不推"的规则三换成：逐个放置时，对当前物体和已放好的上下文物体各采 2048 表面点，双向清距损失（穿进去罚、离开超过 ε=0.005 也罚），只优化平移，Adam 300 步。比 scene_fix.py 的 AABB 推开细得多——沙发和地毯那种"贴合但盒子相交"不会被误推，椅子腿伸进桌子底下这种真穿插才会动。地面用无限平面，墙做了第 2 条后也进上下文。

  • SDF 可用 mesh_to_sdf 或 trimesh.proximity 预算网格；SAM 3D 的 mesh 面数高，先 simplify 到 1–2 万面。报告里已有的"穿模体积"指标正好当验收。
  • 支撑图的"未知"（支撑物没分割出来）可以再补一层 VLM 裁决：只把这几个物体连同编号 mask 图发给 Gemini/GPT，按 CAST 的"细粒度关系 → 投票 → 折叠"要父节点。
  • ϕ-Scene 报告这一步把穿深从 0.024 压到 0.001；预计一个场景几十秒，CPU 即可。
不动生成器CPU需 VLM API
2

房间壳：mask + 点云 → 平面多边形（Diorama PlainRecon）

用 labels.txt 里的 wall / floor / ceiling / windows mask 切 MoGe 点云，每块 RANSAC 拟平面，法线夹角 <10° 且距离接近的合并，墙与地求交线定墙脚，墙与墙求交线定墙角，最后把每面墙裁成多边形并挤出薄板。被家具挡住的墙脚按交线延伸补齐——这就是"地板不完整"的修法。作为第二阶段再加"去家具 inpainting → 重估深度"。

  • 产出直接作为第 1 条的静态上下文（墙也参与去穿插），也让"靠墙"这种关系有了目标。
  • SpatialLM 可以并行试一下：把同一点云喂给它，看墙段拓扑对不对，对了就省去手写交线逻辑。
不动生成器CPU数据已齐
3

刚体落稳（ϕ-Scene 的 Blender 方案）

SDF 之后再用 Blender 刚体（bpy 可 pip 装，无需 root）：VHACD 凸分解，按支撑顺序逐个释放，模拟 120 帧，15 帧窗口内位姿变化 <1e-4 视为落稳。这一步解决"不穿但重心在外、一模拟就倒"的情况。REST3D 的 CEM 搜索效果更好但要 Isaac Gym，先不上。

不动生成器需 bpy每场景 1–3 分钟
4

把约束塞进 SAM 3D 的采样（MV-SAM3D）

MV-SAM3D 的"layout injection"是在 SAM 3D flow 采样每一步对多个物体的 latent 加"体积重叠惩罚 + 接触"引导，输出再做位姿优化，代码公开且基于 SAM 3D。这是唯一能在生成阶段就避免穿模的现成方案，但需要改我们 inference_pipeline 的采样循环，且多物体要同时进显存。建议在 1–3 落地后再试，用同一批指标对比。

动采样循环代码公开显存要评估
5

不建议现在做的

换成 MIDI / SceneGen / PixARMesh 这类联合生成：没有硬约束、只在合成室内数据上训练、没贴图，形状质量也不如 SAM 3D。它们的价值是当"布局先验"参考（ϕ-Scene 就是可选地用 TRELLIS.2 整体生成做 OBB 校正），不是替代品。

五、该用什么指标

文献里已经收敛出一套物理指标，建议我们照抄，这样每一步改动都能量化，也能和 REST3D / ϕ-Scene 的数字直接比：

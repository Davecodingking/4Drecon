# 闸口看得清 + 场景查看页搬进闸口

2026-09-23。改 `tools/` 下的两个看结果的工具,不动算法、不动产物。

## 为什么要改

**一、人工审候选的时候看不清。** 闸口网页给你看的每张图都是"灰底抠图":只留 mask 里的像素,
外面整片刷成灰的。于是有两种东西判不了 ——

- **在哪**:一个物体飘在灰底上,没有周围的东西当参照,不知道它在画面的哪个位置、挨着什么。
- **是什么**:本来就暗的地方原样暗,看不出是通风管还是别的。office r4 那根通风管就是这么被放过去的,
  事后才靠"这东西根本不该生成"人工删掉。

**二、看不了摆得对不对。** 3D 查看页 `tools/box_fit_view.py` 全仓库没有任何脚本调它
(只有 README 写了命令),每次都要人手敲;而且它把所有数据 base64 塞进一个 **6.9 MB 的单文件 html**,
只能整份发出去看。结果是:想看一眼"这轮的 layout 合不合理"要额外走一轮。

## 改之前是什么样(事实,改的时候别记错)

| 东西 | 现状 |
|---|---|
| `tools/gate_ui.py` | 176 KB 单文件服务。`PAGE` 是 1800 多行的 HTML 大字符串。路由 `/img/word｜inst｜cand｜pick｜recall` 全部返回 `cutout_rgb()` 出的灰底特写(灰 210、pad 12%、缩到 size 见方居中)。帧走 `Store._frame()` 的 LRU,不直接 imread |
| `tools/box_fit_view.py` + `box_fit_view_template.html` | 把一个 `data` dict `json.dumps` 进模板的 `<script id="data" type="application/json">__DATA__</script>`,出 `<r1>/10_box_fit_view.html`。office r6 实测 **17.7 秒 / 6.9 MB**(7 个人、140000 背景点) |
| 物体的键 | 两边天然一致:3D 页是 `word + id`,闸口是 `word + oid`。**不需要新的 id 体系** |
| 闸 | 室外六道闸在 `drive.py`;**室内链没有闸**(`pipeline/indoor_pipeline.py:1328`:"物体链没有闸门,一路跑到底"),只读 `05_review_applied.json` |

## 做什么

### 一、闸口加定位图

`gate_ui.py`:

1. `_gamma(img, m)`:按 **mask 内**像素的灰度中位数 med 算 `g = log(0.5) / log(med/255)`,
   **只在 med < 110 时生效**,g 夹在 [0.4, 1.0]。亮的图一点不动。
2. `Store.locate(word, oid, frame, size=420)`:拿同一张帧和 mask,出**整帧**——
   mask 外面乘 0.45 压暗、物体外接框画 2 px 红框、mask 轮廓描 1 px 红线,长边缩到 `size`。
3. **特写也提亮**:`cutout()` 和 `locate()` 用同一个 g,所以两张图亮度一致,"是什么"和"在哪"都看得清。
4. 新路由 `/img/frame?word=&oid=&frame=&size=`,取代表帧的逻辑和 `/img/inst` 一样(前端带 `frame` 就用那一帧)。
5. 页面:实例卡(`PAGE` 里用 `/img/inst` 那处)的特写**右边**并排放定位图,宽 260;候选抽屉切帧时它跟着切。

不动:`cutout_rgb()` 的构图(灰 210 / pad 12% / 居中);`review_gate.py` 出的联络图 jpg(那是批量出图的另一条路)。

### 二、3D 页变成和闸口同一个网址下的一个 tab

拆成"算"和"看":

1. **算** —— `box_fit_view.py` 加 `--data <路径>`:把现在塞进模板的那个 `data` dict 单独写成
   `<r1>/10_box_fit_view.json`。`--out` 照旧出单文件 html(要发给别人时还用它)。
   **流水线那一步只出 json**,不出 html —— 一轮要刷三次,没必要每次落 7 MB。算法一行不改,只换出口。
2. **模板** —— `<script id="data">` 里是空的时候,页面 `fetch('data')` 去拿;非空照旧(单文件模式)。十几行。
3. **看** —— 新文件 `tools/scene_view.py`:
   - `/3d` 出模板壳,`/3d/data` 出那份 json(gzip),`/3d/state` 出"数据在不在、是哪一步生成的"。
   - 看哪一轮,**从闸口当前的 `Store` 拿 `R1`** —— 闸口顶栏换轮次,3D 跟着换,不自己记一份。
   - 它**只读** `10_box_fit_view.json`。不读点云、不读 glb、不起子进程、不 import 算法模块。
     数据不在就返回一行说明。
4. **挂上去** —— `gate_ui.py` 只加三处:顶栏两个 tab;`do_GET` 里
   `if u.path.startswith("/3d")`;**import 写在函数里**(懒加载)。你不点那个 tab,
   `scene_view` 不被 import,闸口启动速度不变;它挂了 tab 灰掉,闸口照常填照常存。
5. **联动**(键就是 `词#实例`):
   - 闸口 → 3D:按钮带 `#sel=<词>#<实例>`,页面加载时 `select()` 过去、镜头飞到它。
   - 3D → 闸口:选中时顶上出现"回闸口看这个",链接 `/?sel=<词>#<实例>`;`PAGE` 启动读它,
     展开那个词、滚到那一行。同一个端口,所以跳得动。
6. **自动生成**(17.7 秒,前台跑,不用后台):
   - 室外 `drive.py`:第 3 段(量完盒子)、第 4 段(召回合并)、第 5 段(组装 + 物理)各跑一次。
   - 室内 `indoor_pipeline.py` 步骤表加一步 `boxview`,在 `boxfix`、`merge`、`phys` 之后各跑一次。
   - 输入都比产物旧就跳过。
   - 闸 6 不重复生成:闸 5 到闸 6 之间场景没有变化。
   - 闸 2 不出:那时还没量盒子(`box_fit_view.py` 会退回读 `06_all_boxes.json`,但闸 2 时它也还没有)。

## 不做(边界,别往里加)

- 不把 3D 的代码写进 `gate_ui.py`。那个文件已经 176 KB。
- 不让 `gate_ui.py` 起子进程去生成数据。它"只碰一个决策文件、零风险"的定位靠这条;
  数据没有就提示"还没跑到量盒子那步"。
- 不动 `05_review.json` 的字段,不动 `review_gate.py --apply` 的校验。
- 不换 id 体系。

## 怎么验

1. **看得清**:office r6 起闸口,挑几个暗的实例 —— 定位图里看得出它在画面哪、挨着什么;
   提亮之后认得出是什么。拿 `pipe`(通风管)当样例。
2. **懒加载**:不点 3D tab 时 `"tools.scene_view" not in sys.modules`。
3. **两边定位**:闸口点一个物体 → 3D → 点"回闸口",前后是同一个实例。
4. **坏了不连累**:把 `10_box_fit_view.json` 改名 → 3D tab 灰掉,闸口照常保存决策。
5. **单文件还能出**:`--out` 出来的 html 和现在的除了数据来源之外一致,能直接开。
6. **自动出**:室内 `--from boxfix --to boxview`,17 秒量级出 json;第二次跑因为输入没变而跳过。

## 风险

- `PAGE` 是 1800 多行的大字符串,改它容易碰到别处。改动限定在**实例卡那一处 + 顶栏**。
- 6.9 MB 的 json 每次整份拿。本地无所谓;真觉得慢了再切成"壳 + 按需要的实例点",不提前做。

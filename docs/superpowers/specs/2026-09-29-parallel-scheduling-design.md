# 并行调度设计：把 8 张卡用起来

日期：2026-09-29　分支：`parallel-sched`　回退点：标签 `before-parallel-sched`

## 1. 目的

这套流水线是 real2sim 的第一步：一段实拍视频进去，一个 3D 场景（带会动的人）出来，同事拿去微调。目的是给同事省时间。

现在一段 5 秒的视频（nfl1，114 帧）算下来约 25 分钟，全程只用 1 张卡，另外 7 张闲着。

**这次要做到**：同一轮里能同时跑的任务同时跑，各用一张卡。nfl1 的计算时间从约 25 分钟降到 10～12 分钟（以实测为准）。

**这次不做**：

| 不做的事 | 原因 |
|---|---|
| 模型常驻（不重复加载） | 改动大，等多人天天用时再做 |
| 出人那步抽帧 | 可能影响快动作，要单独试 |
| 把网页开放给同事访问 | 先把速度做好 |
| 生成物体（gen）内部拆分 | nfl1 只生成 1 个物体，收益小 |
| 失败后只重跑没完成的步骤 | 现在也是整段重跑，保持不变 |

## 2. 现状

- 驱动（`drive.py`）把流水线分成 6 段（室内 5 段），每段跑完停在闸口等人看。
- 每一段，驱动调一次流水线：`outdoor_pipeline.py --only 步骤a,步骤b,...`。
- 流水线按步骤表的顺序，一步跑完再跑下一步。
- 开跑时 `drive_go.sh` 挑一张空卡，整轮所有步骤都用这张卡。每张卡有一把锁，文件是 `/tmp/outdoor_pipeline_gpu<卡号>.lock`。
- 流水线里有一张 `DEPS` 表，记着每一步需要哪几步的结果。现在只用来判断结果是否过期，不用来排顺序。

nfl1 各步耗时（秒，来自 `logs/timing.tsv`）：

| 段 | 步骤和耗时 |
|---|---|
| 地基 | vlm 34、da3 109 |
| 生成前 | track 222、people_track 85、verify（修好联网超时后约 180～300） |
| 尺度 | people_mesh 684、gen 链约 100、vlm_sizes 68 |
| 逐实例 | solo 91、boxes_wd 151 |

## 3. 设计

分三部分：步骤之间并行、卡的分配、两个慢步骤内部拆分。

### 3.1 步骤之间并行

**规则**：一个步骤，只要它需要的那几步都跑完了，就可以开始。几个步骤同时满足条件，就同时开始。

**依据**：`DEPS` 表。它是唯一的依据，不再另外维护一张"谁和谁能并行"的表。

**做法**：

- 新文件 `pipeline/sched.py`，里面一个函数 `run_graph(要跑的步骤, 依赖表, 启动函数, 最多同时几个)`。
- 流水线收到 `--only a,b,c` 且步骤多于一个时，不再自己一步步跑，而是交给 `run_graph`。
- `run_graph` 为每个可以开始的步骤启动一个子进程：`outdoor_pipeline.py --only <这一步>`。每个步骤在自己的进程里跑，互不影响。
- 依赖表里提到、但不在这次要跑的步骤里的，当作已经完成（它们在前面的段里跑过了）。
- 同时满足条件的步骤，按步骤表里的顺序启动，保证每次运行的顺序一样。

**各段的并行情况**（室外）：

| 段 | 同时跑的几组 | 最后跑 |
|---|---|---|
| 地基 | ① vlm　② da3 → up | — |
| 生成前 | ① track → dedup → relabel → pick → verify → override　② people_track | — |
| 尺度 | ① gen → ratio、meshes → boxes　② vlm_sizes　③ people_mesh | scale |
| 逐实例 | ① solo　② boxes_wd | compare |
| 验收 | assemble → people → phys，然后 ① people_glb　② render | — |
| 收尾 | ① building_scene　② assemble_wd → phys_wd → render_wd | — |

**闸口不变**：并行只发生在一段之内。一段跑完还是停在闸口，人看完再继续。闸口决定改了之后重跑哪些步骤，规则也不变。

**开关**：环境变量 `PARALLEL`，默认 `1`。设成 `0` 就和现在完全一样，一步一步跑。出问题时用它退回旧方式。

**日志**：

- 每个步骤自己的详细日志（`logs/03_track.log` 等）不变。
- 驱动日志里，一个步骤的输出在它跑完时整块写入，格式和现在一样（`== 步骤 [环境] 说明` 开头，`   12.3s` 结尾）。几个步骤的输出不会互相穿插。
- 步骤启动时写一行 `[并行] 开始 步骤名`。
- 正在跑的步骤各有一个标记文件 `<本轮>/logs/.running_<步骤>`，内容是进程号，跑完删掉。步骤的输出要等跑完才进驱动日志，网页和看板靠这个文件知道现在在跑哪几步。
- `logs/timing.tsv` 和完成戳（`.stamp_<步骤>`）不变。

### 3.2 卡的分配

**现在**：一轮开跑时挑一张卡，用到底。
**改成**：每个要用卡的任务，开始时领一张空卡，跑完还回去。

**做法**：`pipeline/_common.py` 里新增 `GpuSlot`，替换三处主循环里的 `GpuLock`（室外、室内、出人）。

领卡的步骤：

1. 先拿到本轮的一个名额。名额数 = 本轮最多同时用几张卡。
2. 按卡号从小到大找：这张卡的锁能拿到，而且卡上没有别人的进程占着显存（超过 2 GB 算占着）。
3. 找到了：把这个进程的 `CUDA_VISIBLE_DEVICES` 设成这张卡，开始跑。
4. 没找到：每 5 秒再找一次，最多等 3 小时。不报错，不和别人挤同一张卡。
5. 跑完：释放锁和名额。

**配置**：

| 名字 | 默认 | 意思 |
|---|---|---|
| `MAX_GPUS` | `8` | 一轮最多同时用几张卡。同事加入后改成 `3` |
| `GPU_POOL` | 全部卡 | 可以用哪些卡，例如 `0,1,2,3` |
| `PARALLEL` | `1` | `0` = 旧方式，一步一步跑 |

默认值写在 `_common.py` 里，改默认值只改那一处。

**保持兼容**：

- 锁文件的名字一个字不改。旧方式启动的轮次、shell 脚本（`gpulock.sh`）和新方式互相认得对方的锁。
- 手工指定卡仍然有效：`CUDA_VISIBLE_DEVICES=3 drive_go.sh ...`，这一轮就只用 3 号卡。
- `drive_go.sh` 不再在开跑时挑卡。

**本轮目录怎么传**：名额和下面的记录文件都放在本轮的结果目录里。流水线启动子进程时用环境变量 `RUN_DIR` 把这个目录传下去，出人那条流水线（它有自己的目录）也用同一个 `RUN_DIR`，这样名额是整轮共用的。

**谁在用哪张卡**：领到卡时写一个文件 `<本轮>/logs/.gpu_<卡号>.json`，内容是步骤名、进程号、开始时间；还卡时删掉。网页和看板读这些文件。进程已经不在的文件当作无效。

### 3.3 两个慢步骤内部拆分

拆分的意思：同一个脚本同时启动 K 份，每份算一部分，各用一张卡。模型代码不动。

**K 怎么定**（每次跑到这一步时现算）：

```
K = 三个数里最小的：要算的个数（人数或词数）、现在的空卡数、本轮还剩的名额
K 至少是 1。K = 1 就和现在一样。
```

**新文件** `pipeline/fanout.py`：分组、启动 K 份、等它们跑完、失败重试。track 和出人共用。

**领卡**：拆分的步骤自己不领卡，由它启动的每一份各自领一张。否则这一步会多占一张卡不用。

#### 出人网格（people_mesh）

- 脚本 `body4d_mesh_5090.py` 已经有 `--ids`（只算这几个人）和 `--out`（输出到哪）。
- 分组按工作量：每个人出现的帧数不同（nfl1：人 1 有 114 帧，人 8 只有 3 帧），分组时让每组的总帧数接近。
- 每份输出到自己的临时目录 `<出网格目录>/_part<k>/`。
- 全部跑完后合并到 `<出网格目录>/`，目录结构和现在一样：
  - `mesh_4d_individual/<人>/`、`focal_4d_individual/<人>/`：按人搬过去，编号换成全体统一的编号。
  - `masks/`：按全体统一的编号重新生成，和现在的做法一样。
  - `relabel.json`、`mesh_report.json`：合并成一份。
  - `rendered_frames/`（检查用的叠加图）：把几份的图叠在一起。
- **只在"补全关"时拆分**。补全开着时，模型要看其他人的遮挡，不能按人拆，K 固定为 1。

**已知的小差别**：合并后的检查视频（`05_mesh_overlay.mp4`）里，不同组的人互相遮挡的前后关系可能不对，颜色可能重复。这个视频只用来检查，后面的步骤不读它。最终的验收视频 `09_people_check.mp4` 是另外渲染的，不受影响。

#### 物体跟踪（track）

- 脚本 `track_all.py` 加一个环境变量 `ONLY_WORDS`：只跟踪这几个词。
- 每个词的结果本来就是单独一个文件（`03_masks/<词>.npz`），不需要合并。
- `03_track_report.json` 现在是脚本跑完时整份写入。拆分后每份写自己的 `03_track_report.part<k>.json`，由步骤合并成一份。
- 这个脚本现在是"一批词共用一次检测"（每批最多 8 个词）。拆分后每份在自己的那几个词里共用检测。

### 3.4 失败处理

**步骤失败**：

- 正在跑的其他步骤继续跑完，它们的结果有效。
- 不再启动新的步骤。
- 流水线以失败退出，写明哪一步失败。驱动就地停，和现在一样。

**拆分里某一份失败**：

- 其他几份继续跑完。
- 失败的那份换一张卡重试一次。
- 还失败：这一步标记失败并停下，写明哪几个人或哪几个词没算出来。

**重跑时只补没算出来的**：

- track：结果文件已经存在的词直接跳过（现在就是这样）。
- 出人：每份的临时目录里记一个 `part.json`，写着这份算的是哪几个人、用的参数、跟踪结果的时间。重跑时，三项都一样的那份直接用，不重算。任何一项不一样就重算。

### 3.5 网页和看板

- 现在显示"正在跑第 N 段 · GPU 3"。改成列出正在跑的每个任务和它用的卡，例如"track（卡 0、1、2），people_track（卡 3）"。
- 一段里可以有多个步骤同时显示"正在跑"。
- 要改的地方：`tools/run_ctl.py`（`state`、`segments_view`、`run_gpu`）、`tools/run_page.py`（顶上那行字）、`tools/watch_run.py`（`parse_drive`）。
- "正在跑哪几步"读 3.1 的 `.running_<步骤>`，"用哪张卡"读 3.2 的 `.gpu_<卡号>.json`。进程已经不在的标记不算。没有标记时（`PARALLEL=0` 或老轮次）照旧看驱动日志里最后出现的步骤名。

## 4. 风险和应对

| 风险 | 应对 |
|---|---|
| `DEPS` 表不全：两个步骤表里看着无关，实际一个读另一个写的文件 | 动工第一步是核对 3.1 表里每一组同时跑的步骤，逐个确认它们读写的文件不重叠。发现漏的依赖就补进 `DEPS`。已知一处：track 读 vlm 的词表，但 `DEPS` 里没写，要补上 |
| 拆分后结果和不拆不一样 | 见第 5 节的验证。不一致的那一步不拆（K 固定为 1），其余照常 |
| 每份都要加载一次模型，拆分收益打折 | 耗时以实测为准。如果某一步拆了反而不快，那一步不拆 |
| 改坏了 | `PARALLEL=0` 立即退回旧方式；代码可以退回标签 `before-parallel-sched` |

## 5. 怎么算通过

**自动测试**（不需要显卡，用假步骤和假卡）：

| 测什么 | 要求 |
|---|---|
| 调度顺序 | 每一步都在它依赖的步骤之后开始；互不依赖的步骤运行时间有重叠 |
| `PARALLEL=0` | 按步骤表顺序一步一步跑，没有重叠 |
| 步骤失败 | 不启动新步骤；正在跑的跑完；退出码非 0 |
| 依赖表检查 | 依赖表里的名字都在步骤表里；没有循环依赖 |
| 领卡 | 两个任务同时领，拿到不同的卡；卡全被占时等待，有卡释放后拿到 |
| 手工指定卡 | 只用指定的那张 |
| 名额上限 | 同时占用的卡不超过 `MAX_GPUS` |
| 分组 | 各组总帧数接近；K 不超过人数、空卡数、名额 |
| 合并 | 合并后的目录结构、编号、报告和不拆时一样 |
| 现有测试 | `tools/tests/run.sh` 全部通过 |

**实跑验证**（nfl1）：

1. `r2`：`PARALLEL=0`，当前代码，从头跑。闸口的选择照抄 `r1`。
2. `r3`：`PARALLEL=1`，从头跑。闸口的选择照抄 `r1`。
3. 对比 `r2` 和 `r3`：

| 对比什么 | 要求 |
|---|---|
| track 结果（每个词的 mask） | 一致 |
| 出人网格（每人每帧的顶点） | 一致 |
| 总耗时 | `r3` 明显少于 `r2`，记录实测数字 |
| 最终验收视频 | 人工看，正常 |

**"一致"的判断标准**：同一步不拆、跑两次，结果本身可能有极小的差别（显卡计算的特性）。先量出这个差别有多大，拆分前后的差别不超过它，就算一致。

生成物体那几步带随机性，不要求一致，只看最终视频。

**室内**：室外通过后，同样的调度代码接到室内流水线，用 office 验证。office 的 `r6_pillarfix` 缺 `07_scene.glb`，验证时新开一轮从头跑。

# carryfit: 被人拿着 / 搬着的物体, 每帧求位置和朝向

室内 / 室外流程把物体当成静止的, 被人拿着的东西(抬的箱子、端的托盘、骑的滑板车)要么在闸口被否掉, 要么被排除不生成。
carryfit 在流程已有结果上补这一块: 人(每帧 MHR 网格)、相机、SAM3 的 mask 都现成, 只求"物体每个关键帧在哪、朝哪"。
第二版(11-06)不再写死"两人抬箱子": 端着、几个人合抬、骑、扔出去用同一套做法。第一版在 fit_v1.py。

## 接进流水线(11-06): 闸 2 勾 held, 后面全自动
1. **闸 2 候选页**: 每个实例卡片多一个 `held?` 按钮, 点了变蓝 `✋ held`(写进 05_review.json 这一行的 `拿着: true`)。
   又在动、又挨着人的实例卡片上有一行蓝字 `likely held: ...`(suggest.py 算的, 只是提示; 闸 2 报告里也列出来)。
2. **落地**(review_gate --apply): 05_review_applied.json 多一个 `拿着的: [{生成名, 词, 实例}]`。
3. **组装**: assemble_scene.py 不把它当静物摆(跳过原因"被人拿着"), 场景里不会多一个不动的副本。
4. **carry 步**(两条流水线都有, 在 people_glb 和 motion 之间; carry_step.py): 每个物体 重跟 mask -> 找网格 -> 拟合,
   结果在 `<R1>/13_carry/<词>_<实例号>/`, 合起来的预览 `13_carry/preview.mp4`, 汇总 `13_carry/summary.json`。
   网格的顺序: 这个实例流水线生成的 -> 这个词的整类网格 -> 闸 2 标了"共用"时同词别的被拿着实例的 -> make_mesh 现生成。
   一个物体失败不拖垮整轮, 闸 5 标红, 不进 FBX。
5. **motion 步**: 被拿着的物体和人、相机一起进 `12_motion/<场景>_scene_people.fbx` 和 `.blend`(物体名 `carried_<词>_<实例号>`,
   每关键帧一个关键帧, 线性插值); 导出后导回来自检, 5 帧包围盒差超过 0.1 cm 就失败。
6. **闸 5**(本轮页第 5 段): "被人拿着的物体"面板, 每个物体一行(缩略图、四段对齐, 低于 0.5 标红、网格从哪来、进不进 FBX),
   下面是预览视频。对得不好又不想要的点"不要"(当场存进 13_carry/去留.json), 再点继续: 驱动只重跑 motion(一两分钟),
   然后留在闸 5 再看一遍; 全部跑完以后再改也能点继续。"要回来"同理。motion 导完把实际导进 FBX 的记进 12_motion/carried.json,
   和决定对不上就算过期(pipeline/carry_decisions.py)。"不要"只管进不进 FBX; 想变回静物要回闸 2 去掉 held。

suggest.py 的门槛按 couplelift / goodfellas / stepup / coupledance / office 定: 箱子、两辆滑板车标出来, 静物、衣服、
远处的树都不标; goodfellas 的托盘标不出来(闸 2 时只跟上 10 帧, 又主要朝镜头走), 要人自己勾。
★ 帧号: 03_masks 的 frame 是帧文件名里的号(0004.jpg -> 4), 相机隔帧取的场景(coupledance)不等于第几个关键帧;
  fit / retrack / make_mesh / suggest 都按文件名对(11-06 修的, 以前只在相机每帧都取的场景上对)。

## 一条命令(第二版)
```
carryfit/carry.sh <r1> <词> <实例号>          # 例: carryfit/carry.sh data/indoorOutput/goodfellas_tray_indoor/r1 tray 3
MESH=<glb> carryfit/carry.sh ...              # 流水线没给它生成网格时(滑板车被室外排除了)指定网格; 没有网格先用 make_mesh.py 生成
CF_CARDS=7 carryfit/carry.sh ...              # 只用这几张卡(流水线在生成时别和它抢卡)
```
依次做: retrack.py(拿已有 mask 里露得好的几帧当种子, SAM3 前后双向重跟这个物体) -> fit.py(拟合) -> to_blend.py(加进
12_motion 的 blend, 另存)。输出在 carryfit/runs/<场景>_<词><实例号>/: preview.mp4(原图 | 渲染 | 叠加, 绿圈 = 碰着的手 / 脚)、
metrics.json、carry_poses.npz、<场景>_scene_people_carry.blend。一个物体约 1-3 分钟。
- make_mesh.py: 从重跟的 mask 里挑一帧(面积大、不贴边、不挨着人)给 SAM 3D 生成网格。
- preview_multi.py: 同一段里几个物体画进一个视频; to_blend.py --src 可以往同一个 blend 里加第二个物体。
- debug_overlay.py: 原图上叠 mask(蓝)、拟合轮廓(绿)、碰着的手(黄)、远近和 IoU, 调试用。

## 第二版做法(fit.py 开头有完整说明)
- 接触: 手 / 脚投到画面上离 mask 够近 -> 粗判; 粗拟合后按三维距离再判(< 8cm 碰上, > 20cm 松开)。"拿着" = 手碰着,
  或手刚松开 0.4 秒内物体还贴着人。
- 起点: 24 个直角朝向(以拿着它的人的身体朝向为参照)抽帧批量初筛, 留 3 个。
- 损失: 轮廓(soft IoU + 二维倒角距离; 人只挡得住他身后的东西) + 握点(每只碰着的手在物体上有个握点, 可以慢慢滑) +
  拿着时相对身体朝向转得慢 + 不穿插(SDF) + 不入地 + 运动平滑(脱手离地时 = 重力, 没人拿时 0.5g 以内的减速不罚) + 在相机前面。
- 修补: 轮廓连续对不上的片段(放下 / 扔出之后朝向变了), 单独按相机方向重试 24 个朝向。

## 第二版结果(11-06, 默认参数; IoU = 真人以外的像素)
| 视频 | 物体 | 整体 IoU | 分四段 | 用时 |
|---|---|---|---|---|
| couplelift(两人抬) | 箱子 1.06x0.53x0.47 m | 0.82 | 0.75 / 0.71 / 0.85 / 0.88 | 58 s |
| goodfellas 10-14 s(一人端) | 托盘 0.45x0.20x0.09 m | 0.86 | - / 0.90 / 0.89 / 0.70 | 71 s |
| stepup3d 0-5 s(骑 + 扔) | 女生的滑板车 | 0.53 | 0.71 / 0.45 / 0.45 / 0.51 | 157 s |
| 同上 | 男生的滑板车 | 0.52 | 0.51 / 0.52 / 0.60 / 0.22 | 166 s |
滑板车是细杆, IoU 天生低(偏两三个像素就不重合), 看 preview 更准。
同一组参数重跑, IoU 会差 ±0.03(GPU 上的随机性 + 3 个候选朝向谁赢)。

### 第二版迭代记录(实验都在 runs/exp_* 和 runs/v2_*)
- 通用化第一步(握点固定 + 24 朝向)在 couplelift 上 0.79, 318 s: 慢在 24 朝向 x 全部帧一起渲; 改成抽帧初筛 -> 64 s。
- 两人的手距 15 秒里从 0.62 m 漂到 1.19 m(重建的人在慢慢分开), 刚体两头钉不住 -> 握点允许慢慢滑。
- 重建的手离箱子 60-80 cm 就被当成"放手", 箱子飘走 -> "贴着人就还拿着"。
- 两人合抬时"拿它的人"来回跳 -> 粘性换人。
- 托盘竖着拿的那 1 秒转了 90° -> 身体朝向那项放宽(1 -> 3 rad/s); couplelift 后段也从 0.92 到 0.95。
- 托盘那段厨师的手重建错了、没有接触, 托盘跑到相机后面 -> 加"在相机前面"; 试过 DA3 深度项和不封顶的平滑, 都变差, 没用。
- 滑板车 IoU 0.06: 细杆偏一点 IoU 就是 0、没梯度 -> 加二维倒角距离, 滑板车 0.06 -> 0.5, 托盘 0.70 -> 0.85。
- 车扔出去后还贴着腿, 被当成拿着、跟着人转 -> 身体朝向那项只在手真碰着时用; "贴着人"最多 0.4 秒; 没人拿时允许减速滑行。

## 第一版(11-05, 只做两人抬箱子, fit_v1.py)
### 用法
```
# 1. 拟合(fpose 环境, 领一张卡, couplelift 约 70 秒)
carryfit/run.sh --r1 data/indoorOutput/couplelift_indoor/r1 --word box --oid 1 \
    --mesh sam-3d-objects/outputs/cari4d_couplelift_box/cari4d_couplelift_box.glb \
    --out carryfit/runs/couplelift_r1 [--ref couplelift_indoor_r1/preview.mp4]
# 2. 加进流程导出的 blend(另存, 原文件不动; 带自检)
~/venvs/bpy/bin/python carryfit/to_blend.py --r1 data/indoorOutput/couplelift_indoor/r1 \
    --poses carryfit/runs/couplelift_r1/carry_poses.npz
```
- `--word/--oid`: 物体在 `03_masks/<词>.npz` 里的实例(couplelift: 词 box 的 1 号, 就是审核时被否掉的那个)。
- 物体网格: 现在用的是 11-05 测 CARI4D 时从第 0 帧生成的 SAM 3D 网格; 以后应改成从露得最全的那帧生成。
- 输出: `carry_poses.npz`(每关键帧 物体局部 -> DA3 世界, 外加原始网格 -> 局部的变换)、`metrics.json`、
  `preview.mp4`(原图 | 渲染 | 叠加)、`compare.mp4`(上我们 / 下参考)、`<场景>_scene_people_carry.blend`。
- `debug_proj.py`: 把人的渲染轮廓(红)、SAM3 箱子 mask(蓝)、拟合的箱子轮廓(绿)叠在原图上, 调试用(`FR=帧号,...`)。

## 做法(fit.py 开头有完整说明)
- 未知数: 物体长 / 中 / 短三向缩放(全段一个) + 每帧旋转和平移。所有关键帧一起优化, nvdiffrast 可微渲染。
- 起点: 中心沿 SAM3 mask 质心的视线、深度取两人手中点的深度(他们托着箱底, 箱子在手上方); 长边沿两人手的连线; 另一条边朝天
  (中边 / 短边朝天两种都试, 取损失小的); 大小 = 两人手距 x 1.1。
- 损失: 轮廓(和 SAM3 mask 的 soft IoU, **被真人挡住的像素不算**, 真人 = body4d 的 mask) + 手贴物体表面(鲁棒, 0.3)
  + 人体穿进物体超过 4cm 的部分(手附近 25cm 不算, 10) + 平滑 + 弱约束: 朝天的轴别歪(0.05)、三向比例(0.1)、两人的手在长边两端(10)。
- 先在 1/8 分辨率、轮廓模糊过的图上粗对齐(手的权重再乘 0.2), 再到 1/4 分辨率细调。

## couplelift 结果(couplelift_r1)
| 时间段 | 0-3 s(弯腰抬起) | 3-7 s | 7-11 s | 11-15 s |
|---|---|---|---|---|
| 轮廓和 SAM3 对上(真人以外的像素, IoU) | 0.67 | 0.88 | 0.86 | 0.93 |
| 四只手到箱子表面, 平均(cm) | 1.1 | 1.0 | 1.8 | 1.5 |
| 人(手附近以外)穿进箱子最深(cm) | 5.5 | 4.2 | 0.5 | 0.0 |

箱子 1.02 x 0.58 x 0.51 m(参考结果 1.16 x 0.62 x 0.66)。blend 自检: 反算回局部系中心偏差 0、半长 0.5。

### 迭代记录(都在 runs/ 下, 指标是同一段的 IoU)
- v1: 中心放在两人手中点 -> 箱子在手的位置(太低太小), 轮廓项只在边缘有梯度, 拉不动, IoU 0.17-0.43。
- v2: 中心改沿 mask 质心视线 + 粗到细 -> 0.51-0.73, 但箱子偏小(0.91 m)。
- v3-v6: 遮挡改用真人 mask、三向缩放、保持水平、两端约束; 发现"不穿插"一项占起点总损失 95%, 把箱子压小压低(箱子本来贴着身体,
  重建的人有几厘米误差)。
- v7: 穿插加 4cm 容差、权重 100 -> 10, 水平约束 0.5 -> 0.05(抬起时箱子本来就斜) -> 后三段 0.85-0.92。定为第一版默认参数。
- 11-05 用户发现"箱子只有三个面": 网格转到"长/中/短"轴时交换了两根轴 = 镜像, 三角形朝向全翻到里面, 渲染器把近处三个面当背面剔掉
  (之前以为的"男人胸口从箱子侧面露出来"也是这个)。改成镜像时把最短轴反向(mesh_to_local 行列式 +1), 重跑。

## 已知问题
- 0-3 s 两人弯腰抬起: 重建的人本身不太准, 箱子被人挡住的那端长度没依据, 对齐只有 0.69, 箱子比实际斜。
- 为了对齐画面放宽了穿插: 0-7 s 人的身体会穿进箱子约 5 cm(从原视频视角看不出来)。
- 只支持两人抬一个东西; 一个人单手拿东西时朝向只能靠画面, 还没做。
- 物体网格不是自动挑帧生成的; 也还没接进流水线(现在是单独脚本 + 另存 blend, FBX 还没出)。

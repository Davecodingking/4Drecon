# carryfit/inhand: 被拿着的物体"正确地在手上"(第三版, 11-17 起)

第二版(carryfit/fit.py)里物体是世界里每帧自由的刚体, 手只是一个能滑的握点。结果: 手到物体表面 2-3 cm、轮廓 IoU 也好看,
但物体在手里乱转乱滑 —— 从原相机看不出来, 换个角度就露馅。这里换了建模:

    物体位姿(帧 i) = 握持系(人, 手, 帧 i) · G(这一段握持, 固定) · 手内自由度(帧 i, 只有细长物体有)

每段握持只求一个 6 自由度的 G, 这一段所有帧的轮廓一起投票。模糊帧、被挡的帧不单独决定什么, 被 G 带着走。

## 接进流水线(11-17): carry 步的开关, 默认关
```
CARRY_INHAND=1 drive.py --scene <场景> --run <轮次> ...      # 或者直接  CARRY_INHAND=1 python carryfit/carry_step.py --r1 <r1>
```
不设这个环境变量, carry 步和导出跟以前一模一样。设了以后, 每个被拿着的物体:
1. 第二版照跑(它的结果当挂手版的起点, 也是退路)。
2. 挂手版跑在 `<R1>/13_carry/<词>_<实例号>/inhand/`(拟合 -> 手臂 IK -> 指标 + 四格视频 `inhand_view.mp4`)。
3. 验收: 轮廓对齐(挂回世界系的手)不比第二版同样那些帧低 0.10 以上, 而且"在手上"的帧占一半以上 -> 采用:
   `carry_poses.npz` 换成挂手版的(第二版的留作 `carry_poses_v2.npz`), 闸 5 上这一行的轮廓对齐 / 四段也换成它的。
   没过或者跑失败 -> 保留第二版。两种情况 `13_carry/summary.json` 这一行都多一栏 `挂手版`(状态 / 采用 / 原因 / 各项数)。
4. motion 步: 采用了、闸 5 上没点"不要"的物体, 拿着它的那条手臂的修正叠加到导出的人身上
   (`pipeline/motion_export.py` 调 `inhand/inhand_overlay.py`; 摆人的文件一个字节不动, 改动只进 12_motion)。

开了开关以后 carry 步还多管两件事(11-17 晚, 杀破狼逼出来的; 细节在 carry_step.py 文件头):

## 做法, 以及每一步是被哪个现象逼出来的
1. **把人对回画面**(`anchor_person`)。世界系里摆好的人(修过脚、平滑过、挪过)投回画面, 和画面上的人常常差十几到几十厘米
   (雨中曲: 中位差身高的 9%, p90 18%) —— 手不在画面上该在的地方, 物体轮廓怎么都对不上。
   给每个可能拿着它的人逐帧求一个相机系里的平移, 让他的轮廓对上自己的实例 mask(body4d 的调色板 mask, 编号 = 跟踪编号)。
   G、手腕修正、手内自由度都是"相对手"的量: 在对回画面的手上求, 原样挂回世界系的手上。所以输出两份物体位姿:
   `local_to_world_img`(挂在画面上的手, 评 IoU 用) 和 `local_to_world`(挂在世界系的手, 导出用)。
2. **候选握持**: 掌心投到画面上挨着物体 mask 的连续帧。放得宽 —— 只是候选, 对不对由拟合验(轮廓项比最好的段差太多的丢掉)。
   `--grip` 可以由人指定(以后接闸 2)。
3. **每段握持**: 24 个直角朝向(握持系里)[+ 第二版对得最好的几帧] 抽帧低分辨率初筛 -> 留 3 个粗拟合 -> 细调。
4. **手腕修正**(默认开, `--frozen` 关)。手臂不动只求 G: 托盘 IoU 0.86(第二版逐帧自由 0.88), 手腕够准;
   雨伞 0.45(第二版 0.66), 不够。所以每帧给手腕一个修正, 让物体的轮廓反过来修手:
   转角小而且变得慢; 画面平面里几乎不许动(手在画面上的位置可信, 不封顶地罚); 沿视线可以动(远近不可信)。
   物体永远刚性地挂在修正后的手上, 代价是手偏离原重建, 偏多少在 `attach.json` 里如实报。
5. **手内自由度**(`--inhand auto`): 细长物体(rod)允许绕自己的长轴转、沿长轴滑, 都要变得慢。雨伞在手里转、换握的位置靠它。
6. **联合阶段**: 所有握持段一起, 加不穿人、物体运动平滑、同一只手的几段握持 G 差不多就共用(`--tie_deg/--tie_m`)。
   几只手同时拿: 每帧一个主握持(轮廓对得最好的, 带粘性)决定物体位姿; 别的手**单向**去够物体
   (只改它自己的 G 和手腕修正)—— 试过双向, 重建得差的那只手会把物体带歪(托盘 IoU 0.85 -> 0.44)。
7. **手臂 IK**(`arm_ik.py`): 只动那条手臂的 10 个关节参数, 手腕位置残差 0.01-0.2 cm、朝向 0.1-0.4 度, 12 秒。

## 指标怎么读(`inhand_metrics.json`)
- `握点漂移_垂直_cm_p95` / `手内倾斜_度_p90` / `掌心到表面_cm_中位` 三个都过门槛(5 cm / 15 度 / 6 cm)才算这段"在手上"。
  rod 沿杆滑、绕杆转不算错(握法允许), 所以漂移只看垂直杆的分量、转动只看倾斜。
- 量的是物体相对**修过手臂的人**(`--people_params people_refined.npz`): IK 没到位的会在这里现形。
- ★ "在手上"是构造出来的, 这几个数只能证明没出错, 不能证明对。对不对看 `轮廓IoU`(挂在画面上的手) 和四格视频的侧面 / 俯视。

## 11-17 下午加的(看了雨伞的视频"伞没在手上"之后)
前面那版雨伞有 32/180 个关键帧根本没挂上(退回了第二版的漂浮位姿), 指标却报"在手上 0.97" —— 指标只看挂上的那些帧。改了:
- **候选握持**: 掌心离 mask 的距离改用 mask 的长边当单位(细长的东西握在端头外一点, 按面积算会判成没挨着);
  严格条件(贴着 mask)连续成段才算握上, 握上以后用宽松条件前后延伸(滞回) —— 只满足宽松条件的手(路过的人)不算。
- **默认一直在手上**: 标了"被人拿着"的东西, 哪只手都没判上的帧, 最近握着它的手离 mask 不超过一个物体长就还算它拿着;
  握持段里没 mask 的帧也挂着(握姿带着走, 手腕修正 / 手内自由度按时间插值)。
- **细长物体绕掌心转**(手内自由度从"绕杆转 + 沿杆滑"改成"绕掌心转 3 自由度 + 沿杆滑"): 松握的杆子会绕握点转
  (伞搭肩上 / 垂着 / 甩起来), 手腕拧不出来。握点始终钉在掌心。rod 的"在手上"不再要求倾斜小。
- **逐帧选择**(动态规划, 带切换代价): 每帧在"各段握持的提议 / 离手(第二版的位姿, 要好出 0.25 才算)"里选。
  治两个病: 两只手都近时挂错手; 扔出去的东西粘在手上。没给第二版就没有"离手"这个选项。
- **中间的短空档**(夹在两段握持中间、被判成离手的 1.5 秒以内): 固定握姿、只放开手腕和手内自由度重新拟合, 挂回对得好的那只手。
- **哪只手算拿着**: 物体挂在别的手上时, 这只手的提议和物体对得上才算一起拿; 对不上的不进指标、手臂 IK 也不拉它。
- **指标**: 按握姿分段(存了 hold_run); 多了"没挂在手上的帧数 / 关键帧段", 视频里没挂上的帧左上角红字 NOT ATTACHED。
- **跨镜头**(杀破狼): `--oid 0,6,5` 把跨镜头拆开的几个实例号合成一个物体; 10_people.json 里共用跟踪编号的人号算同一个人,
  同一个人同一只手的握姿跨镜头共用(短的 / 对得差的段借最好那段的握姿, 再固定握姿重拟逐帧量);
  物体没被跟上的镜头里, 那个人只要在画面里就沿用握姿挂在同一只手上(朝向取最近一段端头的值, 没有画面依据)。

## 泛化上做了什么、没做什么
- 不认物体叫什么: 手内自由度和指标的分解只看包围盒形状(rod / plate / blob)。
- 不认哪只手、几个人: 所有人的两只手都是候选, 由拟合验。左右手的握持系同一套定义。
- 不依赖第二版: 没有 `--init_poses` 也能跑(24 朝向起步)。
- 不依赖人是怎么摆进世界的: 先对回画面再求。
- **没做**: 落地的大物体(滑板车, 应该物体约束在地面、人 IK 到物体上); 跨镜头(杀破狼: 人和物体按镜头拆成了多个编号,
  要"同一个人同一件武器共用 G"); 握持中途换握法的自动切段; 开合变形(伞); 手指; 闸 2 的握持信息; FBX 里的父子关系。

### 已知问题
- 托盘右手后一段(关键帧 85-117)没挂上: 漂移 26 cm、倾斜 54 度, 手腕已经被拧了 35-56 度还够不着 —— 这只手重建得离托盘太远。
  现在如实判"不在手上"; 要解得靠专门的手部模型或者放开小臂。
- 同一组参数重跑不完全一样: 托盘 IoU 0.85 ~ 0.88、"在手上" 0.65 ~ 0.87, 滑板车的候选握持段也会变(GPU 上的随机性 + 对回画面的结果)。
- 三向缩放约束原来太弱(--w_shape 0.1): 托盘被拉成过 0.44x0.43x0.14 m(网格自己的比例 1:0.59:0.19)。默认改成 2.0 以后三个案例都守住了
  网格的比例(托盘 0.48x0.28x0.09), IoU 基本不变(托盘 0.86 / 雨伞 0.60 / 滑板车 0.56, 结果在 carryfit/runs/inhand_F/)。上面表里的数是改之前的。
